## Reviewed controls retained

Supabase bearer tokens are verified by the Auth user endpoint, not merely decoded. Django defaults to authenticated API access and checks hospital context. SQL derives `auth.uid()`, validates active membership/context expiry/version/purpose, rechecks capabilities inside security-definer functions and rejects cross-hospital FKs. New function search paths are fixed and helpers are not directly executable by ordinary users. RLS remains enabled. No service-role gateway was introduced.

Arrival/assessment/event retry ledgers, independent assessment review, immutable clinical/coordination history and atomic auditing remain. Authenticated users lack direct writes to those records. Database owners remain privileged; triggers cannot prevent a determined database superuser from altering the system. Owner access must be controlled and monitored separately.

Restricted display data remains the four-field server projection; browser hiding is not the privacy boundary. Protected hospital switch/logout/denial races pass local browser tests with cancellation intentionally ignored. No clinical row websocket is opened.
